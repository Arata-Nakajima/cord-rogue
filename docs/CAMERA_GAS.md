# カメラ画像からGASを計算する仕組み

## 流れ（すべてスマホの中）
1. カメラで顔写真を撮る
2. 顔の点検出（MediaPipe Face Landmarker、Apache-2.0、端末内で動作）が478個の点の座標を返す
3. `src/cameraGas.js` が必要な13点を取り出し、撮影チェック（正面を向いているか等）を行う
4. 問題があれば撮り直しを促し、問題なければ `src/gas.js` でGASを計算する
5. **写真そのものは保存も送信もしない**。残るのはGASの数値だけ

## 検出ライブラリの選定
- 採用: MediaPipe Face Landmarker。478点あり、鼻の付け根の幅など必要な点が全部取れる。ライセンスはApache-2.0で、モデルファイル（face_landmarker.task）もアプリに同梱できる
- 不採用: ML Kit（Google）の顔検出は点が少なく、鼻幅の点が取れないため平均顔の比率が計算できない

## アプリへの組み込み（次の工程）
- ネイティブ部品を使うため **Expo Goでは動かない**。開発ビルド（development build）が必要
- 経路の候補: react-native-vision-camera のフレーム処理プラグインとして Face Landmarker を載せる方式が本命。撮影は静止画1枚でよいので、まずは「写真を撮ってから検出にかける」単純な方式で十分
- 画面側の呼び出しは `gasFromMediaPipe(points, { width, height })` の1回だけ。返り値の `issues` が空でなければ撮り直し表示、`gas` がそのまま初期設定画面のGASになる

## 撮影チェックの理由
論文調査で、写真の対称性は頭の向きに大きく左右されることが分かっている（docs/GAS_REFERENCES.md）。横を向いた写真をそのまま採点すると対称性が不当に低く出るため、向き・傾き・顔の小ささを検出したらスコアを出さずに撮り直しにする。

## 注意
- MediaPipeの点は 0〜1 の正規化座標で返る。横と縦で縮尺が違うため、実画像の幅・高さで戻してから計算する（cameraGas.js が処理済み）
- 左右のラベルは自撮りの鏡像でも入れ替わるが、gas.js の全サブスコアは鏡像でも同じ値になる設計なので問題ない
